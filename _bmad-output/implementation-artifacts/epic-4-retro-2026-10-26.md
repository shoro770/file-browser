**Spec-to-implementation reconciliation**

8. **Roving-tabindex repair was already in `Tree.tsx` and was not changed.** `Tree.tsx` has no diff in the range. The priority order the AC demands (surviving row, else nearest surviving ancestor, else selected row, else first row) is in `Tree.tsx` lines 70-80 (`survivingKey`, `tabStopKey`), and the focus-recovery effect there only acts when focus fell to `<body>`, so it does not steal focus from Refresh. `App.refresh.test.tsx:119` ("keeps exactly one tab stop when the focused row vanishes") covers one tab stop with focus on Refresh. One branch (the previous visible row when an ancestor also vanished) has no dedicated assertion that I found. Disposition: accept; part of the browser check (B2).
9. **Collapsed-folder staleness is a documented, tested decision.** A selection under a collapsed folder is probed through its cached parent handle (`tree.ts`, `gathered.opened.get(...) ?? handles.get(...)`). `tree.test.ts:837` and `App.refresh.test.tsx:280` assert it clears when deleted. The two `deferred-work.md` entries (lines 88-93, 106-108) on stale handles after delete-and-recreate are unverified against a real folder. Disposition: accept with B2 as the proof.
10. **Unreadable root reuses the picker-refusal string.** `handleRefresh` sets `denied`, which renders `DENIED_MESSAGE` ("Access to that folder wasn't granted. Choose a folder to try again."), matching 4.3's AC text exactly (`epics.md` line 1112). The `role="alert"` mirror is the same node. As built it matches the spec; whether the wording suits a mid-session read failure (as opposed to a refused picker) is a product question. Disposition: accept; Open question.
11. **The selection is read twice per Refresh.** `refresh()` probes it with `readFile` before publishing, then `usePreview` calls `getFile()` again through `previewSession` when `refreshCount` changes. This satisfies "getFile for the Selection only" (4.2 AC, AD-6) but doubles the call for the selection, and the two reads can disagree if the file changes between them. The preview read wins visibly (it falls to the failure Metadata Card). Source: `tree.ts` refresh probe; `usePreview.ts`. Disposition: accept.

**Diff-scope review (lenses)**

12. **Runtime behavior is unproven: every Epic 4 claim is verified only in jsdom.** The commit body of `83374c7` says so ("NOT RUN in a browser"), and `deferred-work.md` lines 94-105 list four browser checks (1,000-entry timing, revoked-URL flash for image/PDF, scroll position kept, permission revocation and real deletion). jsdom has no layout, scroll, PDF viewer, real folder or timing. NFR2 and NFR4 (about 1,000 entries, expand under 100 ms, open under 300 ms) have no test at all: `grep` found no 1,000-entry case in `tree.test.ts` or `App.refresh.test.tsx`. Disposition: **defer, blocking for the epic's `done` status** (B2).
13. **Revoked object URL during reload.** `previewSession.open` revokes the previous URL immediately (AD-10) while the old image or PDF viewer stays on screen until the new result lands (`usePreview.ts`, keeps `result` during reload). A mounted `<img>` or PDF `<object>` may point at a revoked URL for the reload duration, contradicting "nothing flashes or blanks" (4.2 AC). Source: `deferred-work.md` line 98; not provable headlessly. Disposition: defer (B2), **fix now** if the browser run shows a flash.
14. **Test gaps remain from earlier epics.** `src/components/Tree.test.tsx` does not exist. `Tree.tsx` carries the tab-stop logic this epic relies on and is covered only indirectly through `App.refresh.test.tsx`. Disposition: defer (B1).

This is a **narrowed scope**: the absence of further adversarial findings must not be read as "checked and clean". Story boundaries read but not exercised: 4-1's `refreshCount` consumed by 4-2's reload key; 4-2's `awaiting` announcement against 4-3's clear-and-explain notice; the finally-block busy reset in `refresh()` against a concurrent `openWorkspace`.
