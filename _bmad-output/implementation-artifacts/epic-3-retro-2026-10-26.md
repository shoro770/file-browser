Epic 1 and Epic 2 action items for these stay open. Disposition: **defer** (B1).
4. **One sanitizing chokepoint, as specified.** Markdown and DOCX both go through `services/sanitize.ts` (`sanitize`, line 132). It is an allowlist (`ALLOWED_TAGS` line 15, `ALLOWED_ATTR` line 23). `applyResourceRules` (line 101) turns every non-`#` link into text and every image that is not an allowed inline raster `data:` image into the placeholder. A scheme-less `//host/x.png` passes DOMPurify's `NO_SCHEME` filter (line 33) when `allowDataImages` is on, but `applyResourceRules` then replaces it, so the regexp is not the last line of defense. Source: `sanitize.ts`, read in this run. Disposition: accept.

Source: both files. Disposition: accept. Whether Chromium's PDF viewer works under `object-src blob:` is untested (finding 8).
6. **Tooling still cannot attribute feature commits.** Epic 2 action B4 (make `git_evidence.py` read the `Story:` footer) did not land: the script returned `stories: []` for `67f2545`, `d9f5e56`, `6336d3c` and `3f2bd8e` even though each has the footer. Disposition: **fix now** (B4).

**Diff-scope review (lenses)**

8. **Runtime security proof is missing: the SM-3 and CSP claims are verified only in jsdom.** The epic's central claim, "previewed content cannot make network requests even when hostile", is required to be proven against `vite build` + `vite preview`. Story 3.4 could not run a browser (`deferred-work.md`, 3-4 entry: the sandbox blocked a CDP script), so what exists is `hostile.test.ts` (34 lines), `csp.test.ts` (29) and `rendererLint.test.ts` (71), which read strings and sanitized DOM. jsdom neither loads resources nor enforces CSP. Also unproven: that the PDF `<object>` renders under `object-src blob:` with the viewer frame falling back to `default-src 'self'` (3-3 entry). Disposition: **defer, blocking for the epic's `done` status** (B2).
9. **Hostile coverage is Markdown-only.** `scripts/fixtures/hostile.md` and `hostile.test.ts` cover Markdown. DOCX goes through the same sanitizer, but no hostile `.docx` test asserts zero resource loads end to end, and `check-renderers` scans `src/components/preview/` only, not `src/services/` (3-4 entry on `.style`, `cssText`, XHR). Disposition: defer (B6).
10. **Main-thread cost is unmeasured.** `renderMarkdown` and `renderDocx` run `marked`/`mammoth` and DOMPurify synchronously and ignore `source.signal` mid-conversion (3-1 and 3-2 entries). No timing was taken for a 1 MB Markdown or a large `.docx`. The spec sets a 1 s target for a ~5 MB `.docx`. Disposition: defer (B3).
11. **Blank body during lazy chunk load.** All three renderers use `Suspense` with a `null` fallback (3-1, 3-2, 3-3 entries). The `mammoth` chunk is 95 KB gzipped, so the blank interval is real on first use. Disposition: defer (B3).
12. **Keyboard reach for wide code blocks.** `pre` is `overflow-x: auto` but not a tab stop (3-1 entry), which sits against the AGENTS.md rule that previews stay keyboard-reachable. Not provable without a layout engine. Disposition: **fix now** if the browser check confirms overflow (B3).
13. **`bmad-review` was not run.** This is a headless run, so the lenses were applied inline through findings 2, 4, 5 and 8-12 only. This is a **narrowed scope**: the absence of further adversarial findings must not be read as "checked and clean". Story boundaries (3-1 sanitizer reused by 3-2; 3-3 lazy object URL against `previewSession`; 3-4 lint scope) were read but not exercised. Disposition: B1b.
